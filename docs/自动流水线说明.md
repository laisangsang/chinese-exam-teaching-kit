# 自动流水线说明

本文是不同智能体共享的流程规范。学科内容以[六板块分析规范](六板块分析规范.md)和公开 `config/content_contract.json` 为准，知识状态以[知识库说明](知识库说明.md)和 `config/knowledge_contract.json` 为准。

## 安全边界

- 所有用户材料、提取结果、工作单、正式源稿、媒体中间物和 Word 产物只进入 `.local/`。
- 流水线不调用外部大模型 API，不上传材料，不自动下载 OCR 或转写模型。
- 流水线不执行 Git 提交、推送、发布或外部请求。
- 输入会复制到任务目录并按 SHA-256 去重；原文件不移动、不改写。
- 真实材料绝不能进入公开 `examples/`、`content/`、`knowledge/`、`docs/` 或测试夹具。

## 创建和第一次运行

```bash
cekit init --name 校内练习讲评 --input .local/inbox/校内练习.pdf --input .local/inbox/校内练习答案.pdf
cekit run --task .local/tasks/校内练习讲评/task.json
cekit status --task .local/tasks/校内练习讲评/task.json --json
```

`--input` 可以重复。任务名会转换为跨平台安全标识；同名任务不会被静默覆盖。状态输出只显示项目内相对路径。

## 八个阶段

| 阶段 | 作用 | 可恢复行为 |
| --- | --- | --- |
| `intake` | 校验归档副本与哈希 | 归档存在且哈希一致时复用 |
| `extract` | 提取文字、题号候选和复核记录 | 输入指纹和产物收据一致时复用 |
| `media` | 由注入式本地工具处理新音视频 | 无工具时记为 `degraded`，不阻塞试卷 |
| `knowledge_pre` | 准备分析前检索审计 | 写明后续需逐题检索，不自动生成结论 |
| `analysis` | 等待教师或智能体写正式 Markdown | 内容未通过合同时保持 `waiting` |
| `delivery` | 校验并构建 DOCX 与交付清单 | 内容指纹不变时复用 |
| `knowledge_post` | 记录完成后的反向复核要求 | 新发现只能先进入 `candidate` |
| `verification` | 核验内容和交付证据一致性 | 只能确认 `evidence_ready`，不能代替人工视觉通过 |

任务状态包括 `running`、`needs_user_input`、`failed` 和 `completed`。阶段还可能为 `pending`、`running`、`waiting`、`completed`、`degraded` 或 `failed`。媒体 `degraded` 表示可选能力不足，不等同于整卷失败。

## 分析暂停点

第一次运行通常生成：

```text
.local/tasks/校内练习讲评/work_orders/analysis.md
.local/tasks/校内练习讲评/work_orders/analysis-validation.json
```

智能体必须先读工作单和本规范，再核对 `artifacts/extract/`。正式内容写入任务 `content/`，Markdown 是唯一真源。整卷只覆盖实际存在的板块；单板块不扩张范围。

分析时必须完成三阶段知识流程：

1. 分析前检索：找现有候选方法、历史证据和适用边界。
2. 逐题调用：记录用了什么、为什么适用或不适用。
3. 完成后反向复核：把新发现作为候选，检查冲突，不自动升级稳定状态。

公共 CLI 当前会写入知识审计骨架，但不会替智能体执行学科检索或撰写分析；这一步必须由教师或智能体实际完成。

## 内容校验与恢复

```bash
cekit validate --task .local/tasks/校内练习讲评/task.json
cekit run --task .local/tasks/校内练习讲评/task.json
```

`validate --task` 从任务位置定位 `content/`；也可用 `validate --content` 检查任意项目内目录。修改内容后再次 `run`，系统按指纹使受影响阶段重新执行。完成阶段的产物若丢失、哈希不符或收据无效，也会定向重建。

任务目录采用本地锁，避免两个进程同时改写同一任务。若上次运行意外中断，直接执行相同的 `run --task`；不要手工把 `task.json` 中的阶段改成已完成。

## 答案不完整

没有正式答案时不能停在空白状态。可依据题面形成【文本推导】暂定答案，并写清证据链、可接受边界和需要正式答案裁决的不确定点；不得写成【官方评分参考】，也不得擅自推定分值。

## 后补正式答案

核心库提供 `attach_reference_answers` Python 接口，但当前 CLI 没有“补答案”子命令。开发者可在本地集成中调用：

```python
from pathlib import Path

from chinese_exam_kit.pipeline.answers import attach_reference_answers

attach_reference_answers(
    Path(".local/tasks/校内练习讲评/task.json"),
    [Path(".local/inbox/校内练习正式答案.pdf")],
)
```

接口会归档和去重答案、保存旧内容与输出快照、更新差异账本，并使依赖答案的阶段回到待处理；媒体阶段不会因此重跑。随后执行：

```bash
cekit run --task .local/tasks/校内练习讲评/task.json
```

工作单会给出最新答案版本令牌和 `analysis-receipt.json` 结构。必须先比较正式答案与旧推导、定向修订源稿，再绑定最终内容指纹。正式答案与文本证据冲突时，同时保留官方口径和文本辨析，并触发知识复审。

## 交付状态

自动构建产生 DOCX、`delivery.json`、`delivery-receipt.json` 与视觉检查清单。`verification.json` 中的 `visual_review: evidence_ready` 只证明清单和产物哈希可核验。人工逐页检查与签名规则见[Word 生成与版式验收](Word生成与版式验收.md)。

## 失败与降级判断

- 提取失败：先核对文件格式、PDF 文字层、渲染器与 OCR；扫描 PDF 缺少本地 OCR 时不能假装已提取。
- 媒体降级：保存状态并继续试卷；不要回溯处理未在本次任务中提供的旧视频。
- 分析等待：属于正常人工/智能体暂停，不是错误。
- 内容校验错误：按结构化问题修订 Markdown，不直接修改 Word。
- 视觉问题：修订 Markdown 或构建样式、重新构建并重新逐页检查受影响文件。
