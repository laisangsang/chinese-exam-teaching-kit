# 架构与开发

## 设计目标

项目将公开、原创的程序与真实教学材料隔离：程序、模板、合同和示例可以进入 Git；真实试卷、答案、音视频、提取物、任务状态和 Word 交付只能留在 `.local/`。内容 Markdown 是教师详案的真源，DOCX 是确定性构建产物。

## 主要目录

| 目录或文件 | 职责 |
| --- | --- |
| `src/chinese_exam_kit/` | CLI、任务流水线、提取、校验、知识索引、DOCX 构建与公开发行审计 |
| `config/` | 内容、知识、样式和公开表面合同 |
| `templates/` | 六板块及整卷的 Markdown 结构模板 |
| `examples/original-mini-exam/` | 仅供复现的原创微型案例 |
| `knowledge/` | 公共空索引；不放真实教学知识 |
| `docs/` | 面向教师、智能体和开发者的公开说明 |
| `agent-guides/` | 各类智能体的本地协作指南 |
| `.local/` | 未跟踪的真实任务空间；运行时创建 |

## 开发环境

要求 Python 3.11 或更高版本。使用虚拟环境从源码安装；当前尚未发布 PyPI 包：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Windows PowerShell 的激活方法见[完整安装说明](完整安装说明.md)。安装后先检查本机能力：

```bash
cekit doctor --report
```

## 变更原则

1. 改学科要求时只修改[六板块分析规范](六板块分析规范.md)及相应可执行合同，不在智能体入口复制一套规则。
2. 改流水线边界时只修改[自动流水线说明](自动流水线说明.md)及对应代码和测试。
3. 新能力先写测试，再写最小实现；涉及真实材料的测试使用临时原创夹具。
4. 不将真实题目、答案、教师讲解、个人信息、绝对路径、密钥或二进制交付物加入 Git。
5. 文档中出现的 CLI 命令必须与 `cekit --help` 保持一致。

## 本地测试与发行审计

```bash
python -m pytest -q
cekit release-audit
```

`release-audit` 检查 Git 跟踪的公开表面，重点阻止私有路径、密钥、媒体、大型文件、未允许目录和不安全链接目标。它不能替代人工对版权、授权和匿名化的判断。

## 贡献前检查

1. 运行定向测试和完整测试。
2. 在本机复现原创示例，且不把 `.local/` 产物加入提交。
3. 阅读 `git diff`，确认没有真实题面、私人文件名、邮箱或凭据。
4. 运行 `cekit release-audit`，处理所有 error。
5. 如改动 DOCX 构建或样式，按[Word 生成与版式验收](Word生成与版式验收.md)查看原创示例生成的每一页。

项目尚在首次公开发行准备阶段，未声明远端 CI 已验证，也不自动发布、推送或创建外部请求。
