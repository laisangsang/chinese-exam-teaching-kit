# 常见问题

## 我可以直接处理学校试卷或教师课程吗？

只可处理你有权使用的材料。将原件、答案、录音、视频、提取稿和生成物放在 `.local/`；不要提交、上传或粘贴到外部服务。仓库仅包含[原创微型示范卷](../examples/original-mini-exam/README.md)。

## 为什么第一次运行停在 analysis？

这是正常暂停点。`cekit run` 会准备材料底稿、工作单和审计骨架，但不会替教师或智能体编造学科结论。阅读 `.local/tasks/任务名/work_orders/analysis.md`，依照[六板块分析规范](六板块分析规范.md)写入任务的 `content/`，再校验和恢复运行。

```bash
cekit validate --task .local/tasks/任务名/task.json
cekit run --task .local/tasks/任务名/task.json
```

## 没有正式答案还能继续吗？

可以。基于题面与文本形成的答案必须标为【文本推导】，说明证据、边界和待裁决点；不能标为【官方评分参考】，也不能猜测官方评分分配。正式答案后补后的恢复办法见[自动流水线说明](自动流水线说明.md)。

## `doctor` 报告 OCR、渲染或媒体能力缺失怎么办？

先阅读[完整安装说明](完整安装说明.md)。macOS 可选 Apple Vision OCR；非 macOS 系统需由本地集成注入 `OcrProvider`。项目不下载模型。缺少本地媒体工具会记录降级并继续试卷流程，不应假装转写已完成。

```bash
cekit doctor --report
```

## Word 已生成，是否意味着可以直接打印？

不意味着。自动状态 `evidence_ready` 只代表待验收证据齐备。必须在本机逐页查看 Word 或其本地渲染结果，记录问题、修订源 Markdown、重新构建并复查。清单见[Word 生成与版式验收](Word生成与版式验收.md)。

## 能否把 Word 直接改好后交付？

不建议。Markdown 是内容真源；直接修改 Word 会失去可追溯性。请先改 `content/` 下的 Markdown，再构建：

```bash
cekit build --content .local/tasks/任务名/content --output .local/tasks/任务名/manual-output
```

## 知识库是不是已经有大量稳定规律？

不是。公开知识库当前是可用的空框架。候选、已核验、稳定、待复审和废止的门槛见[知识库说明](知识库说明.md)；原创示例不构成真实试卷的跨卷验证。

## 我可以让智能体自动提交或上传吗？

不可以。流水线不会自动执行 Git 提交、推送、发布或外部请求。智能体操作范围和各工具入口见[兼容性](兼容性.md)。
