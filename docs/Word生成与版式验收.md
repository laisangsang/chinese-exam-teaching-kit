# Word 生成与版式验收

Markdown 是正式内容真源，DOCX 是可编辑、可打印的交付物。任何内容修订都应先改 Markdown，再重新校验和构建；不要只在 Word 里留下无法追溯的孤立修改。

## 构建

独立目录：

```bash
cekit validate --content .local/demo-content
cekit build --content .local/demo-content --output .local/demo-output
```

流水线任务：

```bash
cekit validate --task .local/tasks/校内练习讲评/task.json
cekit run --task .local/tasks/校内练习讲评/task.json
```

构建器读取 `config/docx_style.json` 对应的包内样式资源，设置 A4 页面、页边距、中文字体回退、标题、列表、表格、页眉页脚以及三类证据色彩。生成目录还包含 `delivery.json` 和视觉检查清单。

## 自动状态的边界

自动创建的交付清单只能是：

- `not_run`：尚无视觉证据。
- `evidence_ready`：产物与检查清单已准备，等待人工查看。

只有显式人工复核接口、非空签名、带时区时间和证据齐全时，库层才允许 `passed`。CLI 当前不提供自动写入 `passed` 的命令。不能手改 JSON 冒充复核，也不能把测试通过等同于版式通过。

## 渲染

用本机可用且不会上传文件的工具，将每份 DOCX 转为 PDF 或逐页图片。可使用组织批准的桌面 Word、LibreOffice 或其他本地渲染器。由于字体和分页依赖实际系统，构建成功不能证明另一台电脑上的版式一致。

## 逐页检查清单

每份文件的每一页都要实际查看：

1. 中文无方框、乱码、缺字和异常替换。
2. 正文、表格和图片不越界、不重叠、不穿边、不裁切。
3. 标题不孤立在页底，标题后有有效正文。
4. 表头跨页可识别，行与单元格没有不合理拆分。
5. 页眉标识正确，页脚页码连续。
6. 【官方评分参考】【文本推导】【教学拓展】层级清楚且没有混写。
7. 长引文、文言逐句单元、诗歌逐句单元、作文素材等高风险区域可读。
8. 无异常空白页、内容极少的孤立尾页和不合理大段留白。
9. 封面、首页、尾页、目录或长表等关键页完整。
10. 文件名、题号、板块、答案和分值与本卷一致。

## 修订闭环

发现内容问题时修改 Markdown；发现全局样式问题时修改配置或构建器。重新构建后，至少重看所有受影响页面；分页变化可能传播时，应重新检查整份文档。

建议在任务的 `.local/` 目录保存页面图片、逐页结论和复核记录。证据记录至少包括：文件、页码、结论、问题与修订、复核人、带时区时间。公开仓库不接收这些真实任务证据。

## 人工签名接口

开发者可在本地集成中使用 `DeliveryManifest`、`load_delivery_manifest`、`mark_visual_review` 与 `write_delivery_manifest`。`mark_visual_review` 要求显式签名和带时区 `datetime`；读取已通过记录还要求匹配签名。这是防止自动代码越权宣称通过的安全门，不是电子签名或法律认证服务。

完整任务恢复见[自动流水线说明](自动流水线说明.md)。
