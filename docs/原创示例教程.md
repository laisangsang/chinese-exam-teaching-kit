# 原创示例教程

`examples/original-mini-exam/` 是仓库唯一随附的端到端教学案例。题面、答案、讲义、学校、人物和数据均为本项目原创或虚构，不复制第三方试题、课文、答案或课程材料。文件级声明与摘要见[原创性说明](../examples/original-mini-exam/ORIGINALITY.md)。

## 示例结构

- `source/原创微型示范卷.md`：覆盖六板块的微型题面。
- `source/原创答案与评分参考.md`：原创评分参考。
- `content/`：整卷总览和六份独立详案。
- `knowledge/`：只属于示例的候选知识卡与索引。
- 仓库根 `knowledge/`：公共空库，与示例库隔离。

## 第一次复现

```bash
cekit doctor --report
cekit validate --content examples/original-mini-exam/content
cekit build --content examples/original-mini-exam/content --output .local/demo-output
```

校验应报告通过，构建目录应包含七份 DOCX、`delivery.json` 和 `visual-review-checklist.md`。打开原题、答案与每个板块讲义，观察以下对应关系：

1. 官方答案只进入【官方评分参考】。
2. 证据定位、答案形成和争议边界进入【文本推导】。
3. 课堂追问与迁移训练进入【教学拓展】。
4. 选择题逐项说明原文位置、选项改写、正误判断、设误类型。
5. 主观题呈现审题、证据、关系或整合、评分点、参考答案、失分诊断。

## 练习一次安全修改

把示例内容复制到未跟踪目录，再修改副本：

```bash
cp -R examples/original-mini-exam/content .local/demo-content
cekit validate --content .local/demo-content
cekit build --content .local/demo-content --output .local/demo-rebuild
```

Windows 可在文件管理器中复制该目录，再运行后两条 `cekit` 命令。修改时以 Markdown 为唯一内容真源，不要只改生成的 Word。

## 如何理解示例知识卡

示例卡仅演示四层结构中的总览、题型和方法卡，状态保持保守。它们不会写入公共根知识库，也不能证明某方法已经跨试卷稳定。把示例题当成真实验证材料、把虚构评分参考称作官方答案，都会破坏知识状态的含义。

## 迁移到真实任务

示例用于学习目录、字段和流程，不用于机械套题。真实任务必须重新确认题号、材料、正式答案、评分点和板块范围。先阅读[快速开始](快速开始.md)，再执行[六板块分析规范](六板块分析规范.md)；若某卷缺少板块，只交付实际存在的部分，不复制示例的七文件数量。

## 视觉复核练习

逐页查看七份 Word：封面、标题后首段、表格、长引文、页眉页脚、尾页都要检查。`delivery.json` 中的 `evidence_ready` 只是“有待检查证据”，不是“检查通过”。详细清单见[Word 生成与版式验收](Word生成与版式验收.md)。
