# 快速开始：教师版

这份指南帮助你在本机完成一次可核验的讲评稿制作。你只需要会打开终端、复制命令和编辑 Markdown；若使用智能体，可把[通用智能体指南](../agent-guides/通用智能体指南.md)一并交给它。

## 1. 准备安全工作区

确认电脑装有 Python 3.11 或更高版本。所有真实材料放进仓库根目录的 `.local/inbox/`。`.local/` 已被 Git 忽略，但仍要在提交前运行公开发行审计。

不要把学生姓名、校内资料、购买课程、真实试卷或教师音视频复制到 `examples/`、`docs/`、`content/`、`knowledge/` 等公开目录。

## 2. 安装

```bash
python -m venv .venv
```

macOS / Linux：

```bash
source .venv/bin/activate
python -m pip install -e .
```

Windows PowerShell：

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -e .
```

先检查本机能力：

```bash
cekit doctor --report
```

缺少 `pdf_render`、`ocr`、`video` 或 `transcription` 时不一定影响文字型试卷和 Word 构建；`python`、`word`、`pdf_text` 是核心能力。安装细节见[完整安装说明](完整安装说明.md)。

## 3. 先跑原创示例

```bash
cekit validate --content examples/original-mini-exam/content
cekit build --content examples/original-mini-exam/content --output .local/demo-output
```

打开 `.local/demo-output/` 中的 Word，确认字体、标题、表格、分页和中文显示正常。原创题面、答案与说明见[原创示例教程](原创示例教程.md)。

## 4. 建立自己的任务

下面的名称和文件均为演示写法，请替换成你有权使用且已经放进 `.local/inbox/` 的材料：

```bash
cekit init --name 校内月考讲评 --exam .local/inbox/月考试卷.pdf --answer .local/inbox/月考答案.pdf
```

命令输出会给出任务文件的项目内相对路径，例如 `.local/tasks/校内月考讲评/task.json`。复制该路径继续：

```bash
cekit run --task .local/tasks/校内月考讲评/task.json
cekit status --task .local/tasks/校内月考讲评/task.json
```

系统会在 `.local/tasks/校内月考讲评/` 内复制并按内容哈希去重材料，原文件不会被移动或改写。

## 5. 完成分析工作单

当状态显示 `needs_user_input`，打开：

```text
.local/tasks/校内月考讲评/work_orders/analysis.md
```

同时核对 `artifacts/extract/` 中的文字、题号索引和提取复核记录。不要直接相信 OCR；模糊字必须回看原页。按工作单和[六板块分析规范](六板块分析规范.md)将正式源稿写入任务的 `content/`。

内容必须区分：

- 【官方评分参考】：只放正式答案或评分标准可支持的内容。
- 【文本推导】：依据题干、原文与篇章关系推导的解释。
- 【教学拓展】：背景、追问、变式和迁移，不冒充评分口径。

没有正式答案也可继续，但暂定结论必须放在【文本推导】并写清边界。

## 6. 校验、恢复与构建

```bash
cekit validate --task .local/tasks/校内月考讲评/task.json
cekit run --task .local/tasks/校内月考讲评/task.json
cekit status --task .local/tasks/校内月考讲评/task.json --json
```

校验失败时按问题列表修改 Markdown，再重复上述命令。`run` 可恢复有效断点；内容或答案变化时只重做受影响阶段。流程状态详见[自动流水线说明](自动流水线说明.md)。

## 7. 人工逐页验收

Word 出现在任务的 `output/docx/`。自动结果只会准备 `delivery.json` 和 `visual-review-checklist.md`，不会替你声称页面已通过。请按[Word 生成与版式验收](Word生成与版式验收.md)渲染并逐页检查每份文件，记录复核人、带时区的时间和证据后，才可在你自己的交付流程中标记 `passed`。

## 8. 最后检查

在提交任何公开改动前运行：

```bash
cekit release-audit
```

它只审计 Git 跟踪的公开表面，不会替代你对内容版权、授权范围和匿名化的人工判断。
