# 知识库说明

公共知识库采用“可读知识卡 + 结构化索引”，并预留主题总览卡、题型卡、原子方法卡和真实案例卡四层结构。仓库根 `knowledge/index.json` 初始为空：框架可用不代表知识内容完备。

## 隔离原则

- 私有历史知识、真实试卷、教师课程、内部编号和本机路径不得进入公共库。
- 原创示范卡只放在 `examples/original-mini-exam/knowledge/`，不能冒充公共稳定知识。
- 新任务的知识审计和候选记录留在 `.local/tasks/任务名/knowledge/`。
- 真实答卷与学生失分属于另一类学情数据，不混进当前方法知识卡。

## 卡片类型

| 类型 | 编号前缀 | 目录 | 作用 |
| --- | --- | --- | --- |
| `overview` | `OV` | `overviews` | 一个主题的入口和关系总览 |
| `question_type` | `QT` | `question-types` | 题型任务、证据结构和设误机制 |
| `method` | `MT` | `methods` | 可执行的最小方法及适用边界 |
| `case` | `CS` | `cases` | 可追溯的真实案例证据 |

每张卡必须有元数据：版本、编号、标题、卡片类型、状态、风险等级、适用板块、题型、能力和来源；正文必须包含“知识表述、适用条件、禁止越界、支持证据、反例与冲突”。机器合同见 `config/knowledge_contract.json`；安装后的公开 API 也可直接调用无参数 `load_contract()` 读取随包资源。

## 状态门槛

- `candidate`：候选，尚无独立真实试卷验证。
- `verified`：已核验，至少有一套真实试卷的非推导证据。
- `stable`：稳定；普通方法至少两套不同试卷，高风险方法至少三套不同来源或年份，并优先需要正式答案支持。
- `review_required`：待复审；出现反例、冲突或口径变化后暂停稳定使用，必须记录原因。
- `deprecated`：废止；保留历史、原因和替代关系，不再作为现行方法。

纯【文本推导】和原创示例可以支持候选分析，但不能单独把知识推进到 `verified` 或 `stable`。单套试卷最多推进到 `verified`。出现冲突时优先进入 `review_required`，不能用多数投票静默覆盖。

## 来源与验证

每个来源必须有卡内唯一的 `id`、类型、名称和定位信息。定位使用稳定的项目内相对路径或公开出处，不写本机绝对路径。验证案例通过 `source_id` 精确绑定来源，区分正式试卷、正式答案和文本推导。

影响答案、评分点或考场表达边界的方法属于高风险。其“稳定”不仅要求三套试卷，还需来源或年份具有多样性；没有正式答案支持时即使达到数量，也应保留警告和审慎措辞。

## 三阶段使用

1. 分析前检索：按板块、题型、能力、关键词找候选卡，核对状态和反例。
2. 逐题调用：记录卡片是否适用、采用了哪些部分、为什么不能机械迁移。
3. 完成后反向复核：比较新证据，新增候选或触发复审；不自动升级稳定规则。

自动流水线使用公开 `QuestionKnowledge`、`match_manifest`、`append_audit_event` 和 `CandidateKnowledge` 接口生成可验证收据，不另造无法回放的审计格式。公共库没有达到适用门槛的卡片时，仍须为每题记录 `not_applicable` 决定；不能用一个空壳文件代替完成证据。

检索结果不能替代本卷题面、正式答案与评分标准。知识卡可信度继承其来源；冲突时以本卷高优先级证据为准，同时复审旧卡。

## 公共空库的正确表述

可以说“知识卡结构、状态判定、索引和审计基础可用”；不能说“已经积累大量真题规律”“知识内容已经完备”或“所有方法已经验证”。原创示例用于演示格式，不构成跨试卷验证。
